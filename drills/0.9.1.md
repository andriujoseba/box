# box 0.9.1 — release drill

**WAIVED. No drill was run for this release.**

Waived by the maintainer (@danmt) on 2026-08-04, by explicit operator ruling
recorded on #172 (D3). This file exists because the gate requires a *record*,
not a passing result — a skip is a line in a diff somebody reviewed, never
silence.

## This is the second waiver, and it says so

The [0.9.0 record](0.9.0.md) committed, in the maintainer's name, that the
next release carries a real drill — "a failed drill is a valid record; another
waiver is not." #155 tracks that commitment. **This release overrides it
deliberately and does not pretend otherwise**: the operator ruled that
unblocking a second operator's fleet (the `kimi-box` template is this
release's cargo, and today it is reachable only from a `-dev` install off
main) outweighs holding the tag for a drill this cycle.

The debt does not dissolve — #155 stays open and its commitment rolls forward
intact to the release after this one. What has changed since 0.9.0 is worth
recording so the next cycle starts closer: rig now has a real harness
(`drill/drill.sh` with a record emitter, shipped in rig 0.3.1), so the
"no harness in the family's other legs" half of the 0.9.0 waiver no longer
holds. The remaining gap is procedure, not tooling.

## Why the risk is judged small — stated, not assumed

- The shipping delta is one additive template (`templates/kimi-box/`, a
  byte-shape mirror of the sibling agent seeds), one `box exec` fix already
  rehearsed on real Incus in CI (#170), and a governance conversion touching
  `.github/` and docs. No `bin/box` trust-boundary code changed: template
  discovery is dynamic, and the shared `box-net` profile — the placement
  contract — is untouched.
- The tenant role the new template converges shipped in
  [rig 0.3.1](https://github.com/heavy-duty/rig/releases/tag/0.3.1)
  (heavy-duty/rig#109).

## What this release therefore does NOT prove

Same list as 0.9.0, unchanged, so it is not rediscovered as a surprise:

- **The VM trust boundary.** `ci.yml` says it in its own words: *"What
  container mode canNOT validate is the VM trust boundary itself; that stays
  a real-hardware ritual."*
- **The isolation contract on real hardware** — egress, the sibling drop,
  DNS enumeration, IPv6 off, inbound drop — as measured by `drill/drill.sh`
  against real VMs rather than containers.
- **The combination users receive.** A released box still resolves `RIG_REF`
  to `main` (#150), so a `kimi-box` mint converges whatever rig's main is at
  mint time, not the rig this release was written against.
